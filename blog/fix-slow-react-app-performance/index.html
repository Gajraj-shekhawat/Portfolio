8 Fixes for a Slow React App

Most slow React apps are slow for the same handful of reasons. Measure first, then work down this list.

When a client says their React app feels sluggish, I don't start by sprinkling useMemo everywhere. I open the browser's performance tools and the React Profiler and look at what's actually slow. It's almost always one of these.

The list

  1. Too much JavaScript up front. Split routes and heavy components (charts, editors, maps) so they load only when needed.
  2. Long lists rendered in full. A table with 2,000 rows should render only the rows on screen. Use list virtualisation.
  3. State too high in the tree. Typing in one input re-renders the whole page. Move state down to where it's used.
  4. New objects and functions on every render passed to memoised children. Memoise where the Profiler shows it matters, not everywhere.
  5. Fetching in waterfalls. Component A loads, then fetches; then B loads, then fetches. Fetch in parallel, or on the server.
  6. Heavy images. Serve the right size in WebP or AVIF and lazy-load below the fold.
  7. Big dependencies for small jobs. A full date or utility library for one function. Check your bundle and replace the worst offenders.
  8. Work on the main thread. Heavy calculations can move to a Web Worker or the server.

Check the result

Measure again after each change, on a mid-range phone rather than your laptop. Interaction delays show up in Google's INP metric, which affects how your site ranks (Core Web Vitals explained).
