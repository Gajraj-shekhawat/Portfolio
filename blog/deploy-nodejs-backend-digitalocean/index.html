How to Deploy a Node.js Backend on DigitalOcean (Beginner Guide)

A rented Linux server, your Node.js app, and the few tools that keep it running securely. The setup I use for many small production APIs.

A backend is the part of your product that stores data and does the work behind the app or website. Here is how a Node.js backend is put on a small cloud server at DigitalOcean. It's written for beginners, so you can follow along or understand what your developer sets up.

Step 1: Create a droplet

In DigitalOcean, create a Droplet with the latest Ubuntu LTS, choose a small plan to start, pick a region close to your users (Bangalore for India), and add your SSH key instead of a password.

Step 2: Secure the server

  1. Log in with ssh root@your_server_ip.
  2. Create a normal user with sudo rights and use it from now on.
  3. Turn on the firewall: ufw allow OpenSSH, ufw allow 'Nginx Full' (after installing Nginx), then ufw enable.
  4. Keep the system updated: sudo apt update && sudo apt upgrade.

Step 3: Install Node.js and your app

Install the current Node.js LTS (for example from the NodeSource packages or with nvm), clone your code from GitHub, run npm ci, and put secrets such as database passwords in an .env file that is never committed.

Step 4: Keep it running with PM2

Install PM2 with sudo npm install -g pm2, start your app with pm2 start server.js --name api, then run pm2 startup and pm2 save so it restarts after a reboot or a crash.

Step 5: Put Nginx in front

Install Nginx (sudo apt install nginx) and add a site configuration that forwards requests for api.yourbusiness.com to your app on localhost:3000 with proxy_pass. Nginx handles HTTPS, compression and slow clients so Node.js doesn't have to.

Step 6: Domain and free SSL

  1. Add an A record for api pointing to the droplet's IP (DNS guide).
  2. Install Certbot and run sudo certbot --nginx -d api.yourbusiness.com for a free Let's Encrypt certificate that renews itself.

Next steps for production

  • Turn on automatic backups for the droplet and the database.
  • Use a managed database if you can, instead of running it on the same server.
  • Set up push-to-deploy with GitHub Actions so updates don't need manual logins.
  • Add uptime monitoring and log rotation.

I run several production APIs on DigitalOcean this way. Need it set up properly? See backend development.
