Getting Reliable JSON from LLMs in Production

A demo can live with a model that's right most of the time. An app that saves the output to a database can't. How I make model output dependable.

Most useful AI features end with the model's answer going into code: a lesson plan stored in a database, fields read from an invoice, a category for a support ticket. If the output isn't valid, the feature breaks. Here's what I do on every project.

1. Define a schema first

Write the exact shape you want (with Pydantic in Python or Zod in TypeScript): field names, types, allowed values, required fields. This becomes the single source of truth for the prompt, the validation and your code.

2. Constrain the model

Most model providers and local runtimes now support structured output, where you pass a JSON schema and the model can only produce matching JSON. With a small 3B model on a CPU server, this was the difference between frequent broken outputs and almost none (that project).

3. Validate anyway

Even valid JSON can contain nonsense: a date in the past, a total that doesn't add up, a category that doesn't exist. Validate business rules in code after parsing.

4. Retry with the error

If validation fails, send the model its output and the exact error and ask it to fix it. One retry fixes most problems. Cap retries so a bad input can't loop forever.

5. Keep the task small

  • Ask for one thing per call rather than ten fields of different kinds.
  • Give one good example of the expected output.
  • Use enums for categories instead of free text.

6. Always have a fallback

If the model still can't produce valid output, save the input for review and tell the user honestly. Never store half-valid data silently.
