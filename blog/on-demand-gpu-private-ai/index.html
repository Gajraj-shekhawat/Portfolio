Running a Private AI on a GPU That Sleeps When Nobody Asks

A GPU running all month costs a lot. One that runs only while people are asking questions costs very little. The trick is a tiny server that never sleeps.

When I built Yugam Ask, a chat tool that answers questions about 17 lakh Indian schools, the school didn't want its questions going to a third-party AI provider. That meant running an open model ourselves, on a GPU. And GPUs are expensive to keep switched on for a tool that's used in bursts.

The setup

  • A small gate server that is always on. It costs very little because it does almost nothing.
  • A GPU server running the model with vLLM, and an app server, both created only when needed.
  • A data disk that survives when the servers are destroyed, so nothing is lost.

What happens when someone asks a question

  1. The question reaches the gate.
  2. If the GPU is asleep, the gate creates the servers, attaches the disk and waits until the model is ready. The user sees a short "waking up" message.
  3. Questions are answered normally while people are using it.
  4. After 15 minutes with no questions, the gate destroys the GPU and app servers.

The first answer of the day takes a bit longer. Everything after that is quick. In return, the GPU is billed only for the time people are actually using it.

Things that made it work

  • Keeping the model weights on the persistent disk, so a wake-up doesn't re-download gigabytes.
  • Health checks before routing traffic, so users never hit a half-started model.
  • Being honest in the UI. People don't mind a 1–2 minute wait once a day if you tell them what's happening.
