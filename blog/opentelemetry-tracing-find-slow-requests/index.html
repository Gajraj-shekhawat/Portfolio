Finding Slow Requests with OpenTelemetry Tracing

Logs tell you something went wrong. A trace shows you exactly where the time went, across every service a request touched.

On a platform with several Node.js services, a slow order could be caused by any of them: the order service, the wallet, the promotions engine, a database or a third-party API. Before we had tracing, finding the culprit meant reading logs from five places and guessing. After adding OpenTelemetry with Jaeger, debugging time roughly halved.

What a trace shows

A trace follows one request from start to finish. Each step (an HTTP call, a database query, a queue job) is a span with a start time and a duration. In Jaeger you see them as a timeline, and the slow part is usually obvious at a glance: one long bar, or many small ones in a row that should have run in parallel.

Adding it to Node.js

  1. Install the OpenTelemetry Node SDK and the auto-instrumentations for HTTP, Express, database drivers and Redis.
  2. Start the SDK before your app code loads, with a service name for each service.
  3. Send traces to a collector, which forwards them to Jaeger or another backend.
  4. Make sure trace context passes between services (auto-instrumentation handles HTTP; add it manually for queues).

What to look for

  • One slow database query: add an index or rewrite it.
  • Many sequential calls: run them in parallel or batch them.
  • A slow third-party API: cache, add a timeout, or move it to a background job.
  • Unexpected calls: a service fetching the same data several times per request.

Keep costs sane

You don't need to keep every trace. Sample a percentage of normal requests and keep all slow or failed ones.
