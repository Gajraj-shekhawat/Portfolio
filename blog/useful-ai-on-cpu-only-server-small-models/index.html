Useful AI on a CPU-Only Server: Making a 3B Model Behave

Not every AI feature needs a GPU. A small model on a modest server can do real work if you design around its limits.

Yugam AI runs a chat assistant, a lesson planner for teachers, call recording summaries and a small developer API. All of it runs on a 2 vCPU server with no GPU, using a 3-billion-parameter model through Ollama. People are often surprised that works. It does, with some care.

1. Run one model at a time

A small server can't hold a speech model and a language model in memory together. So jobs take turns: transcribe the call, unload the speech model, write the summary, then load the chat model again. It's slower than a big GPU, but it never runs out of memory.

2. Force the output shape

Small models drift. Ask for a lesson plan in JSON and you'll sometimes get a friendly paragraph instead. Passing a JSON schema to the model, so it can only produce valid output, fixed most of that. The code then validates the result anyway.

3. Keep prompts short and specific

Big models forgive vague prompts. Small ones don't. Clear templates with an example of the expected output gave far better lesson plans than long instructions.

4. Hide the plumbing

The app never exposes which model is behind it. The server picks the model and strips its name from responses, which means I can swap it for a better one later without changing anything for teachers.

5. Plan for the bad day

The server was once rebuilt from backup with all data restored. Simple storage (SQLite), systemd services and a documented rebuild made that a non-event.

When you do need a GPU

For bigger reasoning tasks over lots of data, a larger model on a GPU is worth it, and you can still keep costs down (a GPU that sleeps). For summaries, drafts and structured forms, a small model is often enough.
