Designing an Adaptive Aptitude Test That Doesn't Leak Answers

70 questions in 60 minutes, picked one at a time based on how the student is doing, without ever telling the browser which answer is right.

StreamFit helps Class 10 students and their parents decide between science, commerce and humanities. Shikhar Classes wanted the test to feel fair and to be hard to game. Here's how it works.

The question bank

There are 140 questions across 7 domains, each with 5 difficulty levels and 4 questions per level. A student sees 10 questions per domain, so 70 questions in 60 minutes.

A ladder for each domain

Every domain has its own difficulty ladder. Answer correctly and the next question in that domain is one step harder. Answer wrongly and you stay at the same level. You never move down. That keeps the test encouraging, and the level a student reaches says more than a raw score.

Fighting fatigue

If you test domains one after another, the last domain always looks weak, because students are tired by then. So the domains are interleaved, and the order is shuffled for every sitting. Tiredness gets spread across all of them instead of punishing one.

Keeping it honest

  • The browser never receives the correct answer, the difficulty level or even the domain of a question.
  • The server decides the next question and keeps the score.
  • The final recommendation combines aptitude and academics with weights stored per stream (for example 65% aptitude, 35% academics), which counsellors can adjust without a developer.

Testing the engine

The adaptive engine has its own tests that run without any database, plus a full flow test against a throwaway database. When rules like these change, tests are the only way to be sure every path still works.
