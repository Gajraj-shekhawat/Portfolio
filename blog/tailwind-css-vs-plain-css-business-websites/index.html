Tailwind CSS vs Plain CSS: What I Use for Business Websites

I use both. Tailwind for apps with many screens and a team; plain, well-organised CSS for small, fast marketing sites. Here's how I decide.

People are surprised that my own portfolio uses plain CSS while several client projects use Tailwind. Both are deliberate choices.

Why Tailwind works well for apps

  • Many screens built by several people stay visually consistent, because everyone uses the same spacing and colour scale.
  • You rarely write new CSS files, so styles don't pile up and go unused.
  • Pairs nicely with component libraries in React and Next.js.

Why plain CSS works well for small sites

  • A single stylesheet with design tokens (CSS variables for colours, spacing and fonts) is easy to read and very small.
  • No build step required, which suits a static site that should load instantly.
  • Modern CSS (grid, clamp(), container queries, :has()) covers almost everything frameworks used to be needed for.

What matters more than the choice

  • A small set of tokens: colours, font sizes, spacing, radii. Use them everywhere.
  • Mobile first: design for a 375-pixel screen, then widen.
  • Light and dark themes from the same tokens if you want both.
  • Removing unused styles before shipping.

Whatever you choose, a business website should be fast, readable and easy to update. That's what I aim for in website development.
