Core Web Vitals in Plain English: How to Make Your Site Fast

Three numbers decide whether Google thinks your site feels fast. Here's what they mean and how I got my own site to a 99–100 PageSpeed score.

Google measures how fast and stable your pages feel to real visitors using three numbers called Core Web Vitals. They affect rankings a little and conversions a lot: a slow site on a phone loses customers before they read anything.

The three numbers

  • LCP (Largest Contentful Paint): how long until the main content appears. Aim for 2.5 seconds or less.
  • INP (Interaction to Next Paint): how quickly the page reacts when someone taps or clicks. Aim for 200 milliseconds or less.
  • CLS (Cumulative Layout Shift): how much things jump around while loading. Aim for 0.1 or less.

Fixes that make the biggest difference

  1. Images: use modern formats (WebP or AVIF), the right size for each screen, and set width and height so the layout doesn't jump.
  2. Load the main image first (preload it, high fetch priority) and lazy-load everything below the fold.
  3. Fonts: host them yourself, use only the weights you need, and preload the main one.
  4. Less JavaScript: remove unused libraries, sliders and trackers. Every script competes with your content.
  5. Cache well: serve the site from a CDN with long cache times for files that rarely change.
  6. Reserve space for banners, embeds and ads so they don't push content down.

How to measure

Run your page through PageSpeed Insights and look at both the field data (real users) and the lab test. In Google Search Console, the Core Web Vitals report shows which pages need work. Test on mobile first; that's where most problems show.
