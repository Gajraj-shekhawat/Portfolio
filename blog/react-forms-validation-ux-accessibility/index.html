Better Forms in React: Validation, UX and Accessibility

Forms are where users give you money and leads. Small details decide whether they finish. A practical checklist for React forms.

Sign-up, checkout, admissions, enquiry: the forms in your product are where value changes hands. I've built forms for payments, OTP sign-in and admissions, and the same details decide every time whether people finish.

Design the fields

  • Ask for less. Every field you remove increases completion.
  • Visible labels above fields; placeholders are not labels.
  • The right input types (tel, email, inputmode="numeric") so phones show the right keyboard.
  • Autocomplete attributes (name, tel, postal-code, one-time-code for OTP) so browsers can fill them in.

Validate at the right moment

  • Validate a field when the user leaves it, not on every keystroke.
  • Write errors that say how to fix the problem: "Enter a 10-digit mobile number", not "Invalid input".
  • Keep what the user typed when something fails. Never clear the form.
  • Use one schema (for example Zod) shared by the form and the API, and always validate again on the server.

Make it accessible

  • Connect labels and errors to inputs (htmlFor, aria-describedby, aria-invalid).
  • Move focus to the first error on submit.
  • Make it fully usable with a keyboard, with visible focus styles.
  • Use tap targets of at least 44 pixels on mobile.

Submitting

  • Disable the button and show progress while submitting, to stop double submissions.
  • Show a clear success state with what happens next.
  • For payments and orders, also use an idempotency key on the server (more on that).
